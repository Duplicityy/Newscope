MapAudit requires the exact candidate's disabled profile and produces collision-audit.properties only after at least16 generated maps and all20 bound template variants pass. It verifies actual native collision, every144chunk descriptor across all4quadrants, visible doors/chests, map destruction and lease reuse. A changed server JAR or asset profile invalidates the retained proof. Parent then enables the profile and restarts only the isolated candidate. Never bypass asset checks by changing the running service through reflection.
The last two straight-gauntlet rotations are canonicalized by ordinary generation. After16 normal generated layouts, MapAudit rotates complete generated layouts by180degrees, including floors, room coordinates, anchors, entry, NPCs, chest positions, traps, bypass lanes, guards and door endpoints. This exercises the two opposite native template bindings as real geometry rather than renaming an unchanged layout.
Before building, the audit verifies the actual loaded source archives with bounded XTEA/decompression, complete revision184 landscape parsing and agreement with the native loaded landscape. Each map also captures the real PacketSender's dynamic-region packet into an unregistered in-memory player fixture, decodes the original184 field/bit order and verifies exact source descriptors, unique-region traversal order, key tuples and packet length from all four viewing quadrants. This wire-format check is separate from actual client rendering.

LifecycleProbe requires both actual184 clients online as hdqa1 and hdqa2 and exclusive ownership of those disposable accounts. It walks through the real movement queue, invokes registered native object actions and uses native Hit/death callbacks. Disposable fixture statistics, healing and forced lethal NPC hits reduce test duration; the report explicitly does not claim organic combat pacing or network relogin from these fixtures. Failure keeps logs and reports for diagnosis. Root performs actual client menu/input/screenshots separately.
Every lifecycle entry now waits for a fresh completed184 frame in that exact native map. The test client saves auto-instance-NNN.png and metadata on each instanced scene/quadrant change, plus latest-map-decode.txt during loading. Fatal/OOM errors remove client.ready and retain client-fatal.txt;60seconds without a completed frame fails the test client. The product client JAR remains unchanged.
Use Run-HollowDepths-LifecycleProbe.ps1 with -Preview trap or -Preview chest after successful acceptance to leave hdqa1 at a closed door or unopened chest for real UI input; -Preview status reads the current run UUID, instance and tile without moving it. Preview chest clears its encounter with disclosed forced native hits but never opens the chest. A real network exit/relaunch within the configured300tick grace must preserve the same UUID/instance; lifecycle hook simulation alone is not reported as this network check.

HollowDepthsProbeLoader defines typed probes in the actual running Kilim classloader, found through Instrumentation and a non-null Server.worker. Loading typed probes only with the default agent loader creates a second uninitialized Server and is invalid. Always package each invocation in a distinct JAR path and use a unique probe class name; the JVM can cache a previously loaded agent JAR's contents. Loader accepts CLI PID JAR PROBE_CLASS STAGE; agent argument is JAR|PROBE_CLASS|STAGE. It refuses unmarked or non-loopback game processes.
The loader returns immediately from JVM attachment and runs the probe in a daemon worker; its external CLI waits for stage/probe-status/CLASS.done or .error. The AttachListener remains available to the graceful-stop helper. To cancel map testing, create native-map-audit.cancel in the isolated stage; the active map is destroyed and no proof is emitted. native-lifecycle-probe.cancel stops the lifecycle driver at its next tick and retains actual run state for diagnosis or normal maintenance drain. Remove the cancel marker explicitly before rerunning.
