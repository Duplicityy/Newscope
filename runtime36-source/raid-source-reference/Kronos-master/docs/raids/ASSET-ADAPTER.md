### Runtime archive-read repair

The actual Crondis route smoke test exposed a native IndexFile detail that offline model checks did not exercise: getFile consumes its cached entry. Re-validating the same animation every spear/mouth pulse therefore inflated the whole sequence archive repeatedly and stalled the World worker. The shared asset adapter now caches only successful(group,id) record checks in a concurrent set paired with the exact immutable FileStore object identity. A new FileStore starts a new positive set; null/not-ready stores, absent/one-byte records and invalid IDs are never negatively cached. Existing region displacement/validation caching is unchanged.

A detached verification JVM used the actual native FileStore and actual GZIP inflater with read/decompression counters. Six cold animation/graphic lookups issued six native file reads/two decompressions. After warming,6000public animation/graphic calls issued zero additional reads and zero additional decompressions. Retryable misses followed by availability, a different FileStore identity, and the65535sentinel/bounds passed separately. All24frozen NR06 cache-file hashes remained identical. This ran neither Server.main nor any network/login flow and did not attach to or patch the running private world.
