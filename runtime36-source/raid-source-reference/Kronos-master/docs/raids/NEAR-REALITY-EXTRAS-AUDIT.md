## Donor defects to avoid copying blindly

- `XamphurHandler.java:28..30` uses50votes and30seconds, while messages still say60seconds and death text says150votes. Logic and visible text need one agreed configuration.
- `GanodermicBeast.kt` computes lost-health fraction, then takes the last phase whose threshold is higher. After the first small hit, that can select phase5 immediately. The five authored attack tables are real, but this comparison needs correction during a native port.
- `GauntletRewardsChest.kt` uses `rate =- 0.25` for a booster, an assignment to negative0.25 rather than subtraction. Reward probabilities need bounded native policy, not this typo.
- Korasi's cache description says50–150% maximum melee damage, while the exact authored special implementation calculates its own rolled primary hit plus half-max/addition and0..5. Documentation and code are not perfect parity; port the agreed behavior explicitly.
- No source-only audit proves any of these native host ports are gameplay complete. Authentic asset availability, compilation, and live combat correctness remain separate checks.

## Safe order after raids

Import exact custom assets into a new append-only cache candidate first; retain frozen Dungeoneering IDs and every prior overlay. Native Kotlin/Zenyte modules cannot simply be copied into Kronos Java8. Port isolated native controllers and item hooks, gate genuinely missing assets, and maintain a per-feature receipt. Keep all extra systems out of the raid release's claims until actually implemented.
