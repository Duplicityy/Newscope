# Newscape automation architecture

One game-thread session owns one activity at a time. The private feature flag and exact OWNER group are checked on requests and during a run. Other controllers keep their own behavior. iDungeon and raid start hooks arbitrate control when the feature is enabled. Stop and Pause release only the session's native actions, and a locked native action is allowed to finish its own cleanup where required.

The activity API separates dispatch and recovery from the session scheduler. Native routines retain XP, combat, inventory, bank, collision, depletion, locks and item requirements. Gathering chooses viable local targets and uses ordinary bank transactions for eligible generated supplies. Production uses the materials the owner carries. Farming runs one nearby crop patch through real interactions and yields during growth. No driver synthesizes game rewards.

Progression uses real base levels, enabled skills and a dependency-aware ordering that generally gathers before producing. It stops or records a blocked activity when local access, supplies or encounter eligibility fail. A second bounded pass retries blocked activities only if the first pass earned XP. It keeps skill progress in normal character persistence. Selected skill, goal, master switch and enabled-skill settings use normal character saves. The running session is transient.

Ordinary skills pulse every two world ticks. Boss modes observe the actual encounter every tick and use existing client-equivalent actions. Thermonuclear Smoke Devil reads native Slayer, gear and KC rules. Vorkath's six read-only notifications mirror actual fireball target tiles, acid pool positions, freeze and summon transitions. Zulrah exposes phase, form, transition, Jad alternation and melee target to its controller. These hooks do not replace native attacks.

Windows and older owner clients can use the native dialogue. Android v38 adds a separate portrait activity launched from its existing game menu. It forwards an allowlisted request through the local ART/HotSpot bridge into the current authenticated game connection. The private server replies with nonce-correlated, byte-bounded system-message chunks. The portrait panel has no separate network listener or credentials. Its requests expose only server-approved drivers. Status is refreshed periodically, while Pause and Stop use the same action ownership rules as the game UI. The existing landscape game and renderer still operate through their own Activity.
