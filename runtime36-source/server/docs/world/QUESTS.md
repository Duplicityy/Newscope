# Newscape world quests

River Watch is an original Newscape quest for the Lumbridge area. It uses existing game objects, tools, inventory items, and animations.

## Playing River Watch

1. Open **Minigames → OSRS World** and read the signpost at the west approach to Lumbridge's bridge.
2. Accept the commission, then inspect the east road signpost and search the survey crate by the axe shop. The two readings can be collected in either order.
3. Use the observations to report the fault at the first signpost. The journal repeats your findings.
4. Take an ordinary hammer to the east signpost and repair the latch. Buy a hammer at Newscape's existing General Store if you need one.
5. Return to the first signpost to collect **1,250 coins**. If your inventory has no room for the payment, the commission remains ready to claim.

| Site | Object | Tile | Action |
| --- | --- | --- | --- |
| Commission notice | Signpost 18493 | 3235, 3228, 0 | Read |
| East road gauge | Signpost 18493 | 3261, 3230, 0 | Read |
| Survey ledger | Crate 366 | 3228, 3205, 0 | Search |

## Server implementation

WorldQuestBook binds the three installed objects by ID, tile, type, and rotation after world travel initializes. Registration skips the quest if any expected action is missing or already assigned. Other placements of the same object IDs keep their existing behavior. Object routing uses the native packet path. Quest choices check the player's proximity and the actual object again when selected, and no quest action runs in PvP, Wilderness, or a pending teleport.

The scene interactions are personal to each player. Survey readings, diagnosis, repair, and payment use explicit stage transitions. The nullable `worldQuests.stages` field saves stable quest keys and stages through normal player snapshots. Old saves start at the unaccepted stage. The existing quest points configuration is independent of this quest journal.

The last stage and the reward are committed in the same local account snapshot. Correcting a full inventory or overfull coin stack leaves the claim available. Definite write failures restore the unpaid stage and original inventory slot. If a write may still commit, the native account lock protects the snapshot while a bounded world event checks the outcome. The host's existing durable save barrier can wait up to five seconds by default on the game thread during this one-time claim. Normal stage updates enqueue asynchronous snapshots. The quest is enabled on registered local account worlds.

- **Inkle Ink** separates serializable story state from its presentation. The pinned implementation saves current flow, variables, and story position, and the software license is MIT. River Watch uses Newscape's existing Gson persistence. Its Java manager and step handlers provide useful journal and tracking patterns. A playable quest still needs authority over world interactions, saved state transitions, and rewards on the server. [QuestManager.java](https://github.com/Zoinkwiz/quest-helper/blob/b9b93706618a7b7fe7e5ea30e9a9ef35ba09673e/src/main/java/com/questhelper/managers/QuestManager.java), [QuestStep.java](https://github.com/Zoinkwiz/quest-helper/blob/b9b93706618a7b7fe7e5ea30e9a9ef35ba09673e/src/main/java/com/questhelper/steps/QuestStep.java), [license](https://github.com/Zoinkwiz/quest-helper/blob/b9b93706618a7b7fe7e5ea30e9a9ef35ba09673e/LICENSE)
- **OpenRune**, permissive ISC-style license, has real Kotlin server quest modules. Its manager stores typed player attributes and registers journal rendering separately. - **TSPS**, BSD-2-Clause, has a real server runtime that stores quest stages in player attributes, updates client progress, emits stage and completion events, rejects repeat completion, and runs reward hooks. Newscape's installed cache supplies object, item, and animation definitions. The project still lacks integrated server quest scripts across the full revision 242 world. Implementing additional original quests requires site and action verification against the installed cache, locally authored progression and dialogue, explicit access requirements, and representative save and playthrough checks. River Watch uses its own narrative and reward logic with the installed assets.

## Validation

- Read the three object placements and action labels from the installed cache's actual Lumbridge scenery archive. All three are ground-floor objects in square 12850.
- The detached state suite passed 212 Java 8 and Gson 2.8.2 checks covering both survey orders, skipped and repeated choices, reloads at every stage, existing saves, unrelated quest data, rollback, and unknown save data.
- The detached native playthrough passed using installed maps, the actual object and dialogue handlers, and isolated fixture saves. It covered a wrong diagnosis, a missing hammer, a full inventory, a committed payout, and player reload. The fixture did not open a desktop or phone client.
- Client playthrough should verify walking from the arrival to each landmark, native menu and dialogue entry, the hammer repair animation, inventory capacity refusal, persistence after logout, and a single payout after logging in again.
